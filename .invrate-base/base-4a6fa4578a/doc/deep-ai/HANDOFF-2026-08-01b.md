### Two crashes, both found by reading a dead box

1. **Dangling target city** (`79b5efc9d0`). `deep_op_launch()` hoisted
   `game_city_by_number(op->target_city)` out of the member loop and
   called `dai_gothere()` inside it. `dai_gothere()` moves the member,
   and deep takes undefended cities by walking into them — an emptied
   city is destroyed, freeing the struct — so every member after the one
   that won dereferenced freed memory. **The wave's own success corrupted
   the rest of its own launch.** One cause, two assertions depending on
   what reoccupied the block: `same_pos()` on a null tile (this killed
   EAST2) and `dai_gothere_bodyguard()` on a tile with a null unit list
   (reproduced locally, same candidate/config/seed, same turn).
2. **NaN from `0.0/0.0`** (`a8cbeeddec`). `deep_catchment_average()`
   divides by a weight sum that is exactly 0 when `site_overlap_weight`
   is 0 and the catchment is fully overlapped. **`MAX(0, NaN)` does not
   clamp**, so it reached `cr->total >= 0`, failed, returned NULL, leaked
   the cityresult and silently dropped the site — 148×/generation. This
   **biased the optimiser** rather than merely adding noise: candidates
   with a zero overlap weight were scored on fewer surviving sites than
   candidates without one. That is why machine A's run was killed rather
   than allowed to finish.

Plus `50cc52b908`: one failed game used to abort a 22-hour run.

### The happiness column — `findings/happiness-ladder.md`

A Temple's want is **structurally zero**. `advdata.c:91-100` keeps the
entire `Make_Content`/`Force_Content` family inside an `#if 0` TODO, so
such a building keeps `ADV_IMPR_ESTIMATE` and `base_want()` returns 0 on
its first line (`daicity.c:1529`). Its whole want is
`35 × min(amount, citizens unhappy RIGHT NOW)` — zero in exactly the city
about to need it. **No knob can scale a zero**, so the previous handoff's
"tune ECON and watch the ladder" test could never have worked.

Unhappiness is the **soft** size cap: the city still grows, but each new
citizen must entertain instead of work. W03 priced only the hard cap.

## 5. TRAPS (each cost real time)

- **The agent sandbox runs with `--unshare-pid`: every Bash call has its
  OWN PID NAMESPACE.** `pgrep`/`ps`/`pkill` in one call cannot see or
  signal processes from another call. This is the most expensive trap of
  the session because it yields a *convincing false negative*: five local
  benchmark batches were declared dead on `pgrep -c freeciv-server`
  returning 0, and every one was still running. They reached **69
  concurrent games on 12 cores, load average 73**, which then made
  everything look pathologically slow — producing a suspected perf
  regression in the content credit and a batch failure blamed on an OOM,
  neither of which was real.
  - Run the check with the sandbox disabled to see the true table.
    `readlink /proc/<pid>/cwd` attributes each server to its run — that
    is how strays were separated from the human's live Europe game (port
    5556, cwd `/home/sweettea/freeciv`) before killing anything.
  - **Filesystem state (`DONE`, `saves/`) is shared and reliable. Trust
    it over process checks.**
- **Kill the TUNER first, then the servers.** Reverse order lets tune.py
  respawn a batch in the gap: 22 orphans on EAST1 and 16 on EAST2
  survived into a new run and stole half the CPU until found by cwd.
- **`pkill -f "tune.py"` over ssh kills its own shell** — the remote
  `bash -c` command line contains the pattern. Use `pkill -x`.
- **`tune.py` resumes from `DONE` markers.** Always a fresh `--out` dir
  when the binary changed.
- **`git bundle --all` is 394 MB and times out.** An incremental bundle
  against a commit both boxes already have is ~30-50 KB. Git also
  refuses to fetch into a checked-out branch — `git checkout --detach`
  first.
- **Five paired seeds cannot baseline `lategame-80`.** It read the CM
  presence baseline as 1.0399 where ten seeds read 1.0026 — enough to
  invert a verdict, and it nearly shipped a regression.
- **Do not trust an OOM line without checking its timestamp and
  process.** Freeciv servers are ~68 MB each, measured, and RSS is flat
  across a game (69,780 KB from turn 3 to 19) — no leak, and 40
  concurrent games cost ~2.7 GB.
