# Session brief — autopsy: which tuned blocks lose to compiled defaults

The true-lean A/B (STATUS 2026-08-15, commit 0fb019e551 and the
voiding entry before it) left one live finding: **compiled defaults
beat the tuned pv3 package on three venues**. That indicts some part
of the tuned block set wholesale — most plausibly the fear/floor
family — but nobody knows WHICH blocks. This epic finds out. Diagnosis
only: no code changes, no new knobs, no tuning runs.

## Method

- Read the 2026-08-15 STATUS entries first for the three venues and
  the exact deficit sizes; reuse those venues (or the two cheapest of
  the three if game budget binds).
- Block-wise ablation between compiled defaults and pv3.ini, using
  the block structure in benchmark/tuning-blocks.ini as the unit.
  Bisect by family, not one block at a time: round 1 splits the
  tuned blocks into ~4 families (fear/floor, cm/economy, military/ops,
  site/settler — adjust to the real block list), each arm = defaults
  + that family's pv3 values. Round 2 splits the guilty famil(ies).
- tune.py --evaluate on TRAINING seeds (--seeds
  benchmark/seeds/train.txt), --count 8-16. This is diagnosis, not
  optimisation, but holdout seeds stay untouched anyway.
- Budget cap: ~250 games total. If the bisection wants more, stop and
  report the partial tree — a two-round narrowing is already a win.
- Every arm ini generated by SCRIPT from pv3.ini + defaults (dump the
  compiled defaults via the existing tune-audit/knob machinery, do
  not hand-type values), awk-dedupe-checked, and verified loaded via
  the game.log deep-tuning read-back line on one game per arm.

## Guards

- One binary pinned WITH libfreeciv.so into your own stage dir; own
  worktree, own build/; ports 7300-7349; jobs <=4 (two sibling epics
  share the box).
- Paired per-seed diffs, not means-only; report sign counts.
- Deliverable: STATUS entry with the ablation table (family -> holdout
  of blame), the guilty block list, and the recommended follow-up
  (which blocks a pv4 should simply drop). Commit any generation
  script under benchmark/. No behaviour code changes anywhere.
