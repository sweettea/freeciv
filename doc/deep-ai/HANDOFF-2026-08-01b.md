### Two crashes, both found by reading a dead box

1. **Dangling target city.** `deep_op_launch()` hoisted the target
   lookup out of the member loop; `dai_gothere()` inside the loop can
   end the target (deep walks into undefended cities, and an emptied
   city is destroyed), so every later member dereferenced freed memory.
   **The wave's own success corrupted its own launch.** Killed EAST2.
   Reproduced locally at the same turn; fixed and re-verified.
2. **NaN from `0.0/0.0`.** `deep_catchment_average()` divides by a sum
   of weights that is exactly 0 when `site_overlap_weight` is 0 and the
   catchment is fully overlapped. `MAX(0, NaN)` does not clamp, so it
   reached an assertion, returned NULL, leaked the cityresult and
   dropped the site — 148×/generation on EAST1. **This biased the
   optimiser**, not just the noise: candidates with a zero overlap
   weight were scored on fewer surviving sites. That is why A's run was
   killed rather than allowed to finish.

Plus `tune.py` no longer lets one failed game abort a 22-hour run.

### The happiness column (`findings/happiness-ladder.md`)

A Temple's want is **structurally zero** — `advdata.c:91-100` keeps the
whole `Make_Content` family inside an `#if 0` TODO, so `base_want()`
returns 0 on its first line. **No knob can scale a zero**, which is why
the previous handoff's "tune ECON and watch the ladder" test could
never have worked. Unhappiness is the SOFT size cap; W03 priced only
the hard one.

Measured (6 paired mixed lategame-80, only the weight differing):
happiness buildings 2.1 → 39.6 per 100 cities, specialists/city
0.747 → 0.525, max size 9 → 15, score 1.047 → 1.063.

**The score is NOT a result** — 1.6pp over 3 paired seeds is inside the
noise floor. The mechanism is certain; the value is not. The campaign
now tunes `horizon_content_weight`, and 39.6/100c against baseline's
4.0 suggests the placeholder 1.0 is too hot.

## 4. TRAPS FOUND THIS SESSION

- **`pkill -f "tune.py"` over ssh kills its own shell** — the remote
  `bash -c` command line contains the pattern. Use `pkill -x
  freeciv-server`, or pgrep-and-filter.
- **`tune.py` resumes from `DONE` markers**, so relaunching into the
  same `--out` dir after a code change silently replays stale games.
  Always use a fresh dir when the binary changed.
- **Local background batches get reaped.** `nohup setsid` locally does
  NOT survive (it does over ssh); `xargs -P` and 40-way `&` batches both
  died. The harness's own background mode worked at ≤12 concurrent.
  Five batches were lost to this before giving up and using the boxes.
- **A full `git bundle --all` is 394 MB and times out.** An incremental
  bundle against a commit both boxes already have is 30 KB.
- **Do not trust an OOM line without checking its timestamp and
  process.** One was misread this session as evidence for a local
  memory problem that did not exist: freeciv servers are ~68 MB each,
  measured, and RSS is flat across a game (no leak).
